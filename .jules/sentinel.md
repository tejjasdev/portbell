## 2026-10-06 - Missing Write Deadline Due to Dynamic App Delays
**Vulnerability:** The HTTP server lacked a write deadline (write timeout) when no artificial response delay was configured. This omission left the application vulnerable to Slow Read Denial of Service (DoS) attacks, where an attacker could slowly read responses and hold server connections open indefinitely.
**Learning:** `http.Server.WriteTimeout` cannot be used safely if the application intends to hold requests open intentionally (e.g., simulating a 30s delay response or holding a long-poll connection). If `WriteTimeout` is set on the server, it enforces a hard global timeout. Therefore, `WriteTimeout` was omitted, but doing so without alternative dynamic deadlines leaves endpoints unprotected.
**Prevention:** When building servers that simulate long delays or handle long-polling, standard `http.Server` timeouts may be too restrictive. Instead of removing write deadlines completely, use `http.NewResponseController(w).SetWriteDeadline(...)` per-request to enforce a timeout that accommodates the expected specific response delay (e.g., `time.Now().Add(expectedDelay + 30*time.Second)`).
